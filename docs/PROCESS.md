# PitHub Development Process

## 1. Purpose

PitHub uses Lewis University Software Engineering Course' **Scrum-based Agile development process** to organize work, deliver incremental improvements, and maintain effective team collaboration.

Our process focuses on:
- Incremental feature development.
- Continuous testing and improvement.
- Clear communication and accountability.

---

## 2. Sprint Structure

Our team works in **two-week sprints**.

Each sprint:
- Begins on Monday and ends on Sunday.
- Starts with Sprint Planning on the first Tuesday at 2:00 PM.
- Uses Discord for asynchronous daily updates.
- Ends with a Sprint Review and Sprint Retrospective.

Our team uses each sprint to plan, develop, test, review, and improve the PitHub application.

---

## 5. GitHub Workflow
GitHub is used for source control, issue tracking, pull requests, and collaboration.

The development process includes:
- Selecting work from the Sprint Backlog.
- Creating or updating GitHub issues.
- Developing through feature or fix branches.
- Testing and reviewing changes.
- Merging completed work into the project.

The main branch should remain stable and contain reviewed code.

---

## 6. Backlog Management
The Product Owner maintains and prioritizes the Product Backlog.

Each backlog item should contain:
- A clear description of the requested functionality.
- Priority and estimated effort.
- Acceptance criteria when applicable.
- Current status and assigned responsibility.

Our team refines backlog items as requirements change or become clearer.
